# GitHub workspace

Repository views load automatically: selecting or opening a repository loads its branches, switching to Commits or Pull requests loads that view, and selecting a branch loads its commits. The branch picker uses retrieved branch names and refreshes commit history when changed. Branches and pull requests refresh after creation; comments refresh after posting. Refresh remains available for retrying or checking for newer changes. Repository tabs wrap onto another row on narrow screens without scrollbars.

Saved GitHub connections retain a verified `githubLogin` in the encrypted registry. Account labels use that username even while disconnected and after restarting. Opening the GitHub page fills in missing names on older connections through authenticated `/user` lookups, without enabling those connections. Unavailable lookups preserve existing names. Changing a connection's credentials clears its previous identity so the next lookup cannot display the wrong account. Sign-in retrieves and saves the identity before completing.

The dedicated workspace now uses GitHub REST API calls with the saved token. GitHub's hosted MCP gateway rejects repository tools with `public_repo` tokens (`Forbidden: insufficient scopes`), even though account lookup works. REST preserves that scope and supports the workspace without requesting broader account access. The existing connection checks and discovered argument schemas still apply. Repository, commit, PR and comment responses omit unused fields before reaching the renderer. HTTP permission failures keep their actual meaning instead of being reported as network failures.

Validation for the fix: `node scripts/smoke-github-api.cjs` checks request destinations, credential isolation, repository output size, API errors and non-forced commit updates. Read-only calls using the saved account on 2026-10-26 successfully retrieved repositories (including both `rendu` test repositories), branches, commits and pull requests. The local GitHub profile reset is performed by `scripts/reset-github-profile.cjs`, which removes only official GitHub connections through the app API and clears the remembered OAuth client ID.

Open **GitHub** from the sidebar. Use **Sign in with GitHub** to open your browser and authorize the displayed device code. Once authorized, the account connects automatically. **Add GitHub account** stays available while connected; switch browser accounts on GitHub before authorizing another login. Saved connections appear in the account selector, connected identities are retrieved automatically, and the selected account's first 20 owned repositories load without a manual search. Search filters repository names within the selected account's owned repositories. The backend lists owned repositories through `/user/repos?type=owner`, filters ownership again, and checks the token's identity before all repository actions. Global GitHub search and other owners are excluded, including manually entered repositories. A personal access token and existing connections to `https://api.githubcopilot.com/mcp/` remain available. Tokens use the existing encrypted plugin store and are not returned to the renderer. Enable the parent plugin in Settings if using a connection imported with a plugin.

Sophon's registered public OAuth client ID is included in the app. Users can sign in directly without registering an app or entering an ID. No client secret is required or bundled. Developers can override the app registration with `SOPHON_GITHUB_CLIENT_ID`; the selected registration must enable **Device Flow**. Browser sign-in requests only `public_repo`, not `repo` or `read:user`. Returned grants must confirm exactly this scope before the token is saved. This follows GitHub's [documented device flow](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#device-flow). Sign-in supports cancellation, expiry and polling backoff. Expiring access tokens require signing in again; automatic token refresh is not implemented.

Previously granted broad access is not reduced by this code change. Revoke Sophon in GitHub Settings → Applications → Authorized OAuth Apps, remove the old connection in Sophon Settings → Plugins, then sign in again. The `public_repo` scope still includes broad public-repository permissions; it does not provide fine-grained control over deploy keys, hooks or administration.

For private exceptions, use **Access selected private repositories** with a fine-grained token created on GitHub using **Only select repositories**. Grant only Contents, Pull requests and Issues as needed; keep Administration and unrelated permissions off. The form accepts fine-grained tokens, but cannot inspect or narrow their repository grants: repository selection is enforced by GitHub. OAuth does not offer individual private-repository selection. A GitHub App integration would be needed to provide that selection through browser installation instead of a token.

The workspace supports account verification, repository name search within the selected account, opening an owned `owner/repository` directly, paginated branches and commit history, branch creation, open pull requests, reading the first 20 PR conversation comments, posting comments, and opening pull requests. Select a branch or enter its name to set the destination.

**Commit & push** publishes full text-file contents as one remote commit through `push_files`. It does not stage local working-tree changes or run `git push`. The existing MCP argument and approval-preview size limits apply; large changes must be split. Direct workspace actions run when the user clicks their button, without repeated native approval dialogs. The official GitHub endpoint also skips the generic MCP enable warning. Endpoint restrictions, schema validation, connection revalidation and task guards remain enforced; assistant-initiated tool calls retain their separate approval policy. A transport failure is reported as uncertain and disconnects the connection: inspect GitHub before retrying a write.

Enterprise endpoints, local Git staging, inline review comments, and merging pull requests are not implemented in this workspace.

Validation:

- `npm run build`
- `node scripts/smoke-github-auth.cjs` — OAuth device flow, cancellation, denial, expiry, polling backoff and credential handoff with mocked GitHub responses.
- `npx electron scripts/smoke-visual-sweep.cjs --hidden` — dropdown bounds, long labels and settings layouts at three window widths.
- `node scripts/smoke-github.cjs` — guards, direct actions without approval popups, connection revalidation, concurrent calls, uncertain writes, response parsing and friendly errors.
- `node scripts/smoke-plugins.cjs` — real fixture MCP transports, credential isolation and schema validation.
- `npx electron scripts/smoke-github-ui.cjs --hidden` — production renderer with mocked GitHub responses, account verification, branches, commits, comments, commit/push payloads, and sidebar/header regressions. No real GitHub writes are made.

UI validation uses styled in-app messages with focus and accessible field associations, never browser validation bubbles. GitHub errors remove Electron transport prefixes and explain authentication, permission, network and rate-limit failures.
